# Safety Quest 詳細設計書

## 1. 共通規約

- ソースコードは `src` 配下に配置する。
- Next.js App Routerは `src/app` を使用する。
- DB定義は `prisma/schema.prisma` に配置する。
- 設計書は `doc` 配下に配置する。
- DBはPostgreSQLを想定する。
- 主キーはUUIDとする。
- DB日時はUTC保存、表示は利用者タイムゾーンで行う。
- MVPでは `localStorage` を利用し、DB接続は将来対応とする。
- ポイント種別はKP、SP、AP、合計表示はEPとする。

## 2. 画面別詳細

### 2.1 ログイン

MVPではメールアドレス入力によるデモログインを行う。ログイン後はダッシュボードへ遷移する。

### 2.2 ダッシュボード

表示項目:

- 今月のナレッジ数
- 累計ナレッジ数
- 今月のエンジニア力向上
- 全体的なエンジニア力
- ナレッジ登録数の推移
- エンジニア力の推移
- 今月のナレッジ評価コメント
- AIによるエンジニア評価

最新月次レポートが存在する場合、評価コメントは月次レポートの保存内容を表示する。存在しない場合は現在データから疑似生成する。

### 2.3 ナレッジ登録

左側に登録フォーム、右側にAI整理メモを表示する。

登録項目:

- 発生日時
- 影響の有無
- ステータス
- ナレッジの対象
- 気づき・学びの内容
- 想定される影響
- 原因の自己認識
- 発見契機
- 次に活かす工夫
- 機密情報確認

登録時処理:

1. 必須項目と機密情報確認を検証する。
2. リスク目安を計算する。
3. KPを疑似AI判定する。
4. 通常要約を作成する。
5. ナレッジを保存する。
6. 合計EPにKPを加算する。

AI分析は実行しない。

### 2.4 AI整理メモ

ナレッジ登録中の内容を下書きとして表示する。利用者は自由入力で整理相談ができる。

「下書きを反映」を押すと、AI整理メモの会話履歴をクリアする。ナレッジ登録フォームの内容は保持する。

### 2.5 獲得スキル

入力項目:

- 年月
- 身についたスキル

登録時処理:

1. 入力テキストを検証する。
2. SPを疑似AI判定する。
3. 獲得スキルを保存する。
4. 合計EPにSPを加算する。

年月は `YYYY-MM-01T00:00:00.000Z` として保存する。

### 2.6 実績登録

入力項目:

- 年月
- 達成した実績

登録時処理:

1. 入力テキストを検証する。
2. APを疑似AI判定する。
3. 実績を保存する。
4. 合計EPにAPを加算する。

年月は `YYYY-MM-01T00:00:00.000Z` として保存する。

### 2.7 登録一覧

検索対象:

- ナレッジ
- 獲得スキル
- 実績

検索条件:

- キーワード
- 種別: 全て、ナレッジ、スキル、実績
- ナレッジ状態: 全ステータス、検討中、完了

ステータス条件が全ステータス以外の場合、スキルと実績は表示しない。

検索結果表示:

| 種別 | 先頭表示 | 右端表示 | クリック動作 |
|---|---|---|---|
| ナレッジ | ナレッジ | KP | ナレッジ登録画面へ遷移 |
| スキル | スキル | SP | 参照のみ |
| 実績 | 実績 | AP | 参照のみ |

### 2.8 月次レポート

レポート作成時に、今月のナレッジ、スキル、実績を集計し、月次評価とエンジニア力評価を作成する。

評価内容:

- ナレッジ件数
- スキル件数
- 実績件数
- KP/SP/APの内訳
- 前向きな評価コメント
- 次のステップ提案

同じ年月のレポートは1件にまとめ、再作成時は上書き扱いとする。

### 2.9 設定

表示項目:

- タイムゾーン
- 月次レポート通知
- デモデータ初期化

## 3. データモデル

現行MVPの状態は `AppState` として管理する。

| 型 | 内容 |
|---|---|
| `NearMiss` | ナレッジ登録内容。名称は実装上の旧名だが、画面上はナレッジとして扱う |
| `AcquiredSkill` | 獲得スキル、SP、判定理由、年月 |
| `AchievementRecord` | 実績、AP、判定理由、年月 |
| `AiReport` | 月次評価、エンジニア力評価、対象年月 |
| `SearchListItem` | 一覧画面の横断検索結果 |

DB移行時の正式テーブルは `doc/05_current_database_design.md` を参照する。

## 4. 計算ロジック

### 4.1 リスク目安

ナレッジ登録時に内部的な目安として次を計算する。

```text
rpn = occurrence * severity * detectability
1..19    -> low
20..49   -> medium
50..79   -> high
80..125  -> critical
```

現行画面ではRPNは一覧に表示しない。

### 4.2 KP

初期値10点に対し、次の条件で加点する。最大60KPとする。

- 気づき・学びが一定以上具体的: +10
- 発見契機あり: +10
- 原因認識あり: +10
- チェック、レビュー、自動検証などの語彙あり: +10
- リスク目安がHigh以上: +10

### 4.3 SP

| 条件 | SP |
|---|---:|
| 自動化、テスト、監視、CI/CD、検証など | 50 |
| 設計、レビュー、分析、改善、仕様など | 30 |
| 確認、手順、チェック、共有、整理など | 20 |
| その他 | 10 |

### 4.4 AP

| 条件 | AP |
|---|---:|
| 障害、本番、リリース、改善、削減、解決、復旧など | 50 |
| レビュー、共有、資料、標準化、教育、支援、提案など | 30 |
| 対応、確認、調査、整理、記録など | 20 |
| その他 | 10 |

### 4.5 EP

```text
EP = KP + SP + AP + 既存クエスト由来ポイント
level = floor(sqrt(totalEP / 100)) + 1
```

## 6. エラー設計

| 状況 | 表示・動作 |
|---|---|
| 必須入力不足 | 登録しない |
| 機密情報確認なし | ナレッジ登録しない |
| スキル本文なし | 登録しない |
| 実績本文なし | 登録しない |
| 選択年月のレポートなし | 「選択した年月のレポートは保存されていません。」と表示 |
