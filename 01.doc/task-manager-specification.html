機能・画面仕様書

日々の作業を整理し、期限と進捗をひと目で確認できる個人向けWebアプリ「TaskFlow」の初期リリース仕様。

バージョン 1.0作成日 2026-10-19ステータス：提案・レビュー前

本書は題材・要件を仮定したサンプル仕様書です。既存プロジェクトの実装や確定要件を示すものではありません。

01概要・対象範囲

利用者がタスクの登録、編集、進捗管理、期限確認を一つの画面で行えることを目的とする。初期版はログイン不要の単一利用者向けとし、同一ブラウザ内でデータを保持する。

想定ユーザー

仕事・学習・家事など、自分の作業を管理したい個人。

提供する価値

今取り組む作業と期限を明確にし、対応漏れを減らす。

初期版の対象外

会員登録、チーム共有、クラウド同期、通知、添付ファイル。

状態遷移

未着手↔進行中↔完了

状態は編集画面で任意に変更できる。未着手から完了、完了から未着手への直接変更も可能。期限超過は状態とは別の表示属性とする。

02画面設計

ID / 画面主な要素操作・遷移
S-01 一覧検索、状態フィルター、並び替え、タスク一覧、件数新規作成でS-02、行選択でS-03を開く。
S-02 作成タイトル、詳細、期限、優先度、状態保存後に一覧へ戻る。キャンセル時は入力を破棄。
S-03 編集登録内容、保存、削除、キャンセル保存後に一覧へ戻る。削除は確認後に実行。

一覧画面の表示イメージ（静的サンプル）

マイタスク 2件＋ 新規タスク
検索：すべて　｜　状態：すべて　｜　並び順：期限が近い順
仕様書のレビュー
優先度：高 · 期限：2026-10-20進行中
リリース手順の整理
優先度：中 · 期限：未設定未着手

登録件数が0件の場合は「タスクはまだありません」と新規作成の導線を表示する。検索結果が0件の場合は「条件に一致するタスクがありません」と条件解除の導線を表示する。

03機能要件

ID機能仕様
F-01登録・編集入力検証に成功し、保存が完了した場合に一覧へ反映する。保存失敗時は入力を保持し、エラーを表示する。
F-02削除対象タイトルを含む確認画面を表示する。確定時のみ削除し、取り消し時は保持する。削除後の復元機能は設けない。
F-03検索・絞り込みタイトル・詳細の部分一致検索と、状態の単一選択をAND条件で適用する。検索語の前後空白を除去し、英字の大小は区別しない。空文字は全件対象。
F-04並び替え期限昇順（初期値）、更新日時降順を提供する。期限なしは期限昇順の末尾。同順位は更新日時降順、さらに同じ場合はID昇順。
F-05期限超過端末のローカル日付より期限が過去、かつ未完了の場合に「期限超過」と表示する。当日期限は超過扱いにしない。画面表示時・復帰時およびローカル日付変更時に再判定する。
F-06データ保持ブラウザのlocalStorageへ保存し、再読み込み後に復元する。同一オリジン・同一ブラウザが対象。履歴削除等で消失し得る旨を画面に表示する。複数タブでの同時編集は対象外。

04データ設計

項目 / キー型制約・初期値
ID / id文字列自動生成UUID。編集不可・一意。
タイトル / title文字列必須。前後空白除去後1〜100文字。
詳細 / description文字列任意。最大2,000文字。初期値は空文字。
期限 / dueDate文字列 / nullYYYY-MM-DD形式の実在する日付。任意。過去日も許可。初期値null。
優先度 / priority列挙文字列low / medium / high。初期値medium。
状態 / status列挙文字列todo / in_progress / done。初期値todo。
作成日時 / createdAt文字列登録時のUTC日時（ISO 8601）。編集不可。
更新日時 / updatedAt文字列登録・保存成功時のUTC日時（ISO 8601）。

文字数はUnicodeコードポイント数で判定する。保存キーは taskflow:v1 とし、{schemaVersion: 1, tasks: [...]} をJSON形式で保持する。日時表示は端末のタイムゾーンを使用する。

読み込み時に構造・型・列挙値を検証する。破損データや未対応バージョンの場合は自動上書きせず、一覧の編集を停止しエラーを表示する。利用者が明示的に初期化を確定した場合のみ空データに置き換える。

05非機能要件

区分要件・確認基準
対応環境リリース時点のChrome・Edge・Safariの最新安定版。幅360px以上で主要操作が可能。表は狭い画面で横スクロールを許可。
性能1,000件のデータで、検索・絞り込み操作から表示完了まで500ms以内を目標とする。測定端末とブラウザを受入前に記録する。
操作性キーボードで全操作が可能。フォーカスを可視化し、入力欄にラベルを付ける。状態・エラーは色だけで表現しない。
安全性入力をHTMLとして解釈せずテキスト表示する。アプリから外部へタスクデータを送信しない。機密情報の保存用途は想定しない。
障害時保存容量超過・ストレージ利用不可を検出し、成功表示を出さず再試行を案内する。保存前のデータと入力内容を保持する。

06受入条件

ID / 対応機能確認手順期待結果
AC-01 / F-01タイトルのみで登録し、再読み込みする。1件が復元され、優先度は中、状態は未着手、期限は未設定となる。
AC-02 / F-01空白のみ・101文字のタイトル、および2,001文字の詳細で保存する。それぞれ項目別エラーが表示され、データは変更されない。100文字・2,000文字は保存できる。
AC-03 / F-01状態・期限を編集して保存する。一覧に反映され、作成日時は保持、更新日時は更新される。
AC-04 / F-02削除確認を取り消した後、再度削除して確定する。取り消しでは残り、確定後は再読み込みしても表示されない。
AC-05 / F-03検索語と状態を組み合わせる。両条件に一致する項目のみ表示され、条件解除で全件に戻る。
AC-06 / F-04期限あり・なしのタスクを期限昇順にする。期限が近い順に並び、期限なしは末尾。同順位は定義どおりに並ぶ。
AC-07 / F-05昨日・今日・明日の期限を設定し、昨日のタスクを完了にする。未完了の昨日のみ超過表示。完了後は超過表示が消える。日付変更後も再判定される。
AC-08 / F-06保存失敗および破損データを再現する。失敗を明示し、既存データを自動上書きしない。保存失敗時は編集入力を保持する。
AC-09 / 安全性タイトルにHTMLタグを含めて保存する。タグは文字列として表示され、スクリプト等は実行されない。
